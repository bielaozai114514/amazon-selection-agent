# amazon-selection-agent

亚马逊选品阶段的执行型 Agent。输入一个候选产品，输出「做 / 观望 / 否决」的结论，以及支撑结论的成本、合规、评分与 52 周现金流。

零依赖，只用 Python 标准库。

## 跑

```bash
python agent.py examples/pass.json --out out
```

三个示例覆盖三种结论：

| 文件 | 结论 | 卡在哪 |
|---|---|---|
| `examples/pass.json` | pass | 毛利率 37%，合规干净 |
| `examples/watch.json` | watch | 竞争高、毛利薄，总分不足 60 |
| `examples/reject.json` | reject | 售价低于 15 美元且毛利不足 15% |

批量输入：

```json
{"products": [ {"..." : "..."}, {"..." : "..."} ]}
```

## 七步流水线

1. 读取费率表
2. 落地成本核算
3. 合规扫描
4. 机会评分
5. 52 周三情景现金流
6. 渲染报告
7. 落盘（Markdown + JSON）

每步独立计时，单步失败不会污染其他步骤的结果对象。

## 成本模型

FOB、头程（实重与体积重取大，体积重按 cm³/6000）、保险、关税（MFN + Section 301，按 HS 前四位覆盖）、贴标预处理、入仓、FBA 配送费、平台佣金、仓储、退货损耗，共 15 个字段，输出单件利润、毛利率、投入回报率、盈亏平衡价。

尺寸分档按最长边与围长判定：small standard（≤16 oz、最长边 ≤15 in、围长 ≤30 in）、large standard（≤20 lb、最长边 ≤18 in、围长 ≤54 in）、large bulky。

## 评分

需求 30%、竞争 25%、利润 25%、合规 10%、物流 10%。

五条硬性否决独立于总分：毛利 <15%、售价 <$15、单件 >20 lb、合规扫描高风险、已有 IP 投诉记录。命中即 reject，不看总分。

## 合规

品牌词与特征词命中、按类目的认证清单、七个官方检索入口（USPTO 专利、Google Patents、USPTO 商标、WIPO、CNIPA、EUIPO、Amazon Transparency）。

输出的是核查清单，不是侵权结论。关键词命中和侵权判定之间隔着真实的专利检索。

## 52 周现金流

价格 −10% / 0 / +10%，销量 60% / 100% / 130%，逐月滚动 12 个月，给出售价、单件利润、全年销量、全年利润、期末现金、回本月份、最差月。首批备货投入按 `initial_stock_units × FOB + launch_cost_usd` 计。

## 测试

```bash
python -m unittest discover -s tests -v
```

覆盖：16 oz 分档临界、体积重反超实重、HS 覆盖叠加 301、硬否决三条路径、三情景单调性、回本月份与累计现金一致。

## 设计取舍

**零依赖 CLI，不上 Next.js + Celery + Postgres。** 评估是单次确定性计算，一次输入一个产品，耗时在毫秒级，没有排队与并发需求。引入消息队列和关系库只是把部署成本抬到需要一台常驻服务器，换不来任何计算收益。

**评分与硬否决分离。** 加权平均会把致命项稀释：毛利 8% 的品，其他维度拉满仍能到 80 分，看起来可做。硬过滤器在评分之外独立跑，命中就否决，避免高总分掩盖一票否决项。

**合规只给检索入口，不给结论。** 关键词命中说明“有相似表述”，不说明“侵权”。把前者当后者，是这类工具最常见的错误，也是用户上架后被投诉的直接来源。

**费率表外置。** FBA 费率、佣金比例、关税与 301 都放在 `data/` 下三个 JSON 里，平台调价时改数字即可，代码不动。费率表当前为 2024-04-15 美国站基准。
